# 02 · Folder contract

Every file below has one job. If a file is doing two jobs, split it.

```
design/
├── tokens.json
├── check-contrast.mjs
├── app-icons.mjs
├── illustrations.mjs
├── render-png.mjs        one SVG or HTML artboard → PNG. Not for iOS app icons.
├── app-icons/            <id>.svg
├── illustrations/        <name>.svg
├── fonts/
├── question-packs/
│   ├── packs.json
│   └── <pack>.json
├── redesign/
│   ├── directions.html
│   ├── app.html
│   ├── landing.html
│   ├── <brand>-board.html        (optional: fonts, spacing, components)
│   └── reference/
├── store/
│   ├── README.md
│   ├── logo-icon.html
│   ├── design-board.html
│   ├── build/
│   │   ├── gen_store.py
│   │   ├── design_board.py
│   │   ├── logo_icon.py
│   │   ├── render.sh             (generated, gitignored-or-committed by choice)
│   │   ├── html/                 (generated artboards)
│   │   └── qa/                   (generated QA crops)
│   ├── ios/
│   ├── android/
│   └── marketing/
└── IMAGE_CREDITS.md
```

---

## `tokens.json`
The single source of truth. Structure, naming rules and the contrast gate live in
[`03-tokens.md`](03-tokens.md).

**Test:** could a new engineer build a screen from this file alone, without opening a mockup?

## `check-contrast.mjs`
Runs the `contrastChecks.pairs` table in both modes and exits non-zero on failure. It is the only
automated gate in the design folder, so it must run in CI. Copy from
[`../assets/check-contrast.mjs`](../assets/check-contrast.mjs).

**Test:** deliberately break one token; the script must fail loudly.

## `app-icons.mjs`
Writes review SVGs **and** both platforms' launcher assets in one run. Never let a human
re-export these by hand — the parity between iOS and Android is the whole point.

## `illustrations.mjs`
Same pattern for spot art. Shares one palette and one geometry helper set with `app-icons.mjs`.

**Test:** delete both output directories, run both scripts, `git status` shows only the expected
files, nothing missing.

## `fonts/`
Licensed files, committed (or fetching instructions if the licence forbids redistribution). Record
licence and subsetting. **Never** invent a variable-font axis or a weight the family doesn't ship.

**Test:** open `redesign/app.html` offline — type must still render if fonts are local.

## `question-packs/`
The content deck. See [`08-content-packs.md`](08-content-packs.md).

**Test:** every pack id referenced by the app HTML exists as a file.

## `redesign/directions.html`
Three directions, same screens, side by side, each labelled with its type pairing. A decision
artifact, kept forever for the "why not that one?" question.

## `redesign/app.html`
The main artifact: storyboard **and** mockup. See [`04-storyboard-and-mockups.md`](04-storyboard-and-mockups.md).

**Test:** can a stakeholder find any screen in under 20 seconds? Is every screen's `Live`/`Planned`
label true?

## `redesign/landing.html`
The marketing page built in the *same* CSS and tokens. If the landing page needs its own colours,
the design system isn't done.

## `redesign/reference/`
Untouched inputs: competitor screenshots, research teardowns, spec text, screenshots of the app as
it exists today. Named `NN-slug.png/.txt` so they're referenceable. Never edit these in place.

## `store/README.md`
The store kit's contract: brand definition (wordmark spec + icon spec + source of truth links),
required sizes per channel, regenerate commands, and any platform-chrome notes.

**Test:** a stranger can regenerate every store asset from this file without asking a question.

## `store/logo-icon.html`
Logo concepts and icon variants on one review page: all candidates, real sizes (16 → 1024), light
and dark, plus clear-space and misuse. See [`05-logo-and-icons.md`](05-logo-and-icons.md).

## `store/design-board.html`
Everything on one page: wordmark lockups, icon at real sizes, every screenshot artboard, feature
graphics, social cards. This is the page you show a founder. Generated by `build/design_board.py`
so it can't go stale.

## `store/build/gen_store.py`
Generates store artboard HTML plus `render.sh`. Structure to follow:
`STORE_CSS` (platform chrome) → `page()` → artboard builders → `add()` → `main()` → write
`render.sh`. See [`07-store-and-marketing.md`](07-store-and-marketing.md).

## `store/{ios,android,marketing}/`
Rendered PNGs, grouped by channel then device. Filenames are `NN-slug.png` and are ordered — store
listings are ordered, so the filenames should be too.

## `IMAGE_CREDITS.md`
Every bundled photo: what it shows, where it lives on each platform, and its licence + source.
Not a legal obligation for every source, but the difference between "we can swap that" and
"nobody knows where that came from".

---

## Naming conventions
- **Screens:** `NN-slug` where slug is a verb phrase from the user's side (`03-notes`, `07-privacy`).
- **Icon variants:** bare tokens (`default`, `night`, `mono`, `rosewood`) — no brand prefix inside the file.
- **Illustrations:** `illustration_<moment>` (`illustration_paired`, `illustration_welcome`).
- **Packs:** the pack id is the filename stem.
- **No `.DS_Store`, no `__pycache__`, no `build/html/` in git.** Fix `.gitignore` once rather than
  cleaning up repeatedly.

## Minimum viable folder
If the user only wants a first pass, ship exactly:
`tokens.json` + `check-contrast.mjs` + `redesign/app.html` + `app-icons.mjs`.
Store assets and illustrations can follow once the direction is signed off.
